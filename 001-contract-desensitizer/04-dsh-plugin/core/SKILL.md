# 法律文书脱敏助手（离线 · 可逆 · 实体编号一致）

> 2026-10-30 当前 PDF 规则：已检出的未处置项须先完成处理或明确保留，默认未选中不等于明确保留；风险知悉不能跳过。已有可用位置的待确认项可选择“自动处理”。修改或删除遮盖导致处置失效时，会重新阻断导出。其他识别失败、扫描停止及零处置提示沿用原规则。以下 R89 等历史记录不覆盖本条。

给产品使用者的操作说明见 `references/使用说明.md`。本包同时适配 Windows 与 macOS：Windows 运行包内 `install_windows.bat`，macOS 运行 `install_macos.sh`。macOS安装器会在桌面生成启动和停止两个入口，并把实际技能目录写入应用资源；启动入口在虚拟环境缺失时回退到系统Python，由通用启动器负责恢复环境。不要用上游下载覆盖本地扩展。v1.3.0-dev 是开发候选版；PDF 项目可在服务重启后继续处理、取回原件。

PDF各页均尝试本机OCR补充识别：Windows默认使用RapidOCR；仅在RapidOCR导入阶段触发`ImportError`时尝试Windows系统OCR。系统OCR要求安装包中的Windows.Foundation、Windows.Foundation.Collections、Windows.Graphics.Imaging、Windows.Media.Ocr、Windows.Storage及Windows.Storage.Streams运行绑定可用，并且Windows用户语言配置已安装相应OCR语言包。缺少运行绑定或语言包时会按本页识别失败处理。RapidOCR模型缺失、初始化或识别运行异常、超时均按本页识别失败处理，不自动切换到系统OCR。macOS使用随包提供的Apple Vision程序`pdf_vision_ocr`。有文字层的页面保留原文字层并合并OCR候选，以覆盖文字顺序或版面位置异常造成的漏项；跨行候选按命中字行分别显示和遮盖。页码状态点表示扫描进度，扫描过程可能较慢；有机器提示的页面会聚合为状态点加可展开提示条。补充OCR失败或未取得结果时会提示人工检查，不会将其视为无敏感内容。Apple芯片Mac已完成指定样本OCR实测，仍有漏识别，全部页面均须人工核对；Intel未实机验证。PDF输出只提供脱敏稿，原件保存在本机项目，不向外发件写入映射或项目数据。

## 统一文书脱敏流程

上传DOCX、PDF、TXT或MD后，在对照页核对通用敏感信息、诉讼案号、公文/机构编号和法院名称候选，并逐项选择是否脱敏。格式不足以区分类别的编号候选默认不勾选。案件或项目名称可用于复用自选字段，不改变识别范围或导出清理规则。

Word复核页和PDF导出按钮前显示相同的通用提示：“自动识别无法穷尽文书中的全部敏感字段，识别结果也可能有偏差，外发前请人工核对导出的文件。”其下以灰色小字说明可能未识别的敏感内容将按原文保留；Word确认卡中的具体未扫描项也以灰色小字列出。

PDF进入本机复核页。扫描完成后机器自动处置：能精确改字的候选自动替换；有真实位置框但不能精确改字的候选（OCR分较低、词/行级定位、跨行分段）自动按框处理，代号放不下时整体遮盖；实体分低于0.50的候选与编号候选不自动处理，仅在侧栏提示；需要人工处理的内容列入“需你确认”分组，可在所在页拖框遮盖或明确保留，未处理时按原文导出。每个候选提供“自动/遮盖/保留”三态切换；印章、签名和漏识别文字可手工框选，一键遮盖即完成绑定。文字层与OCR结果按位置合并重复候选；跨行候选按各行字符坐标分段显示和遮盖，空间不足以放置代号时会清除原字而不覆盖相邻正文。表格单元格和独立栏位分开匹配。导出PDF时重建所有页面；导出提示只说明处理边界和结果，不显示坐标或几何诊断。PDF批注及批注人名称可能作为页面内容保留，工具不能单独识别并替换批注人名称，须逐页核对。

上传脱敏文件前必须明确选择“脱敏交易要素”或“保留交易要素”，未选择时不能开始上传；服务端也会拒绝缺失、无效及旧版自动推荐策略，不按文件格式替用户决定。所选策略在PDF、DOCX、TXT和Markdown中使用相同默认选择。PDF导出为像素稿，不生成映射文件，不能用工具还原；金额、日期策略提示在上传和复核页面可见。

PDF实体分、OCR分和定位几何分别处理，不合成最低值。定位按逐字符标签局部判断，空格无字形框不计为坐标不完整，一处粗定位不拖累同页精确候选。实体分低于0.50时默认未勾选，仅在侧栏提示，不阻断导出；OCR分低于0.70的候选由机器自动按框处理；OCR分未提供会明确标示，不伪装为低分。导出为直接操作：仅扫描进行中不允许导出；识别失败页、未定位命中、扫描停止、零处置四类红档须一次“我已知悉，仍要导出”确认，其余信息为非阻断提示，导出区不显示坐标/几何诊断。

旧版PDF项目如果只保存综合分，升级后会保留并标为旧版综合分，不会推算成实体分或OCR分；旧项目不重新OCR，已有勾选、明确保留和手工遮盖全部保留，可直接导出。

## DOCX修订模式

DOCX默认保留并脱敏受支持修订。正文、页眉和页脚中的标准新增/删除文字修订及修订人可扫描、脱敏和由JSON格式映射文件还原；修订标记会保留，不会自动接受、拒绝或移除。Word拖动移动若保存为标准`w:del`/`w:ins`文字修订，且敏感内容可以定位，可扫描、脱敏和还原；跨普通文字与修订文字边界的候选可分段处理。盘点不完整时，无法确认范围的修订段原样保留并在导出前提示，普通正文仍可处理。未能自动改写的已选项按原文保留，清单会列出类型、原文和位置；用户知悉后可以继续导出。

扫描会分别组装接受修订和拒绝修订后的段落文字，因此被拆在多个Word文字片段中的姓名、机构名称和日期可以按完整视图匹配。完全重合的多类型文字候选合并为一次写回，mapping记录全部类型并只还原一次；连续的部分重叠范围合并后写回。结构位置不一致或无法安全组成连续文字的目标仍会触发完整性保护。无冒号的“员工”“法人”等普通词不单独作为强姓名标签；明确字段标签后的姓名仍可识别。代理律师姓名仅在明确的代理、委托、受托、承办、经办律师或律师代理人标签后识别；律师执业编号须有执业证号、执业编号等明确标签并符合受支持格式。

正文、表格、页眉和页脚中的普通文本框（包括VML/DrawingML结构），以及简单、未绑定的纯文本内容控件，已纳入候选扫描、脱敏和映射还原；外发清理会校验其结构。符合简单VML文字路径结构的纯文字水印也会扫描、脱敏并写入mapping。这里说的文本框包括通过Word“插入→文本框”添加的文字，也包括输入在矩形、箭头等绘图形状里的文字；它们不同于普通正文段落。Word为兼容不同版本保留的备用文本框副本（例如VML与DrawingML两种显示版本）无法确认是否都已同步脱敏，页面只显示通用风险说明。受支持的隐藏文字会纳入扫描和脱敏，同时保留隐藏格式。脚注/尾注正文、字段指令、复杂绘图水印、图片内容及部分未支持修订不一定能自动脱敏；导出前会把未处理范围合并为一次知悉确认，确认后可继续导出。低置信候选、按选择保留的字段及移除外链等非阻断信息在导出后汇总。普通字段只扫描可见结果，不扫描指令本身。

无法自动处理的已选项和未扫描范围会在导出前合并为一次知悉确认；确认后原样保留并继续导出，未处理项不会进入mapping，用户可按清单在Word中搜索并自行修改。普通字段的指令和未扫描内容不会被验证为不含敏感信息。DOCX包损坏、XML无效、写入错位、结构完整性校验失败或mapping写入失败仍会阻止导出。原始DOCX不会被改写；修订被接受/拒绝、结构变化、占位符被改写或目标不唯一时，JSON格式的映射文件还原会停止。

## 网址与外部链接

可见网址规则识别不区分大小写的`http://`、`https://`、`www.`以及以`.com`或`.cn`结尾的裸域名；裸域名属于低置信候选，默认不勾选。检测到外部关系时，左右对照内容仍会正常显示；外链设置用于选择导出时移除或保留关系，选择保留后还可复核链接目标候选。DOCX默认移除全部外部关系。超链接显示文字仍保留为普通文字并按可见网址规则扫描；外链图片或对象可能不再显示。选择保留外部关系时，系统会扫描外部超链接目标中符合规则的敏感信息并提供候选；不会扫描目标打开后的远端网页内容，其他类型外部关系目标及Word字段指令中的网址也不扫描。URL候选只覆盖符合当前识别规则且可安全定位的文字，不代表已检查整个链接目标。

PDF会统计可点击链接数量，并在导出前要求确认移除。链接目标不作为候选；页面印出的可见网址仍须按文字候选脱敏或手工遮盖。PDF导出会把页面重建为图片，不保留文本层，可能无法搜索或复制；PDF不生成JSON格式的映射文件，不能通过映射还原。

把合同里的敏感信息**一键替换成可逆占位符**，需要时再**一键还原**成原文。

## 为什么用它，而不是让大模型直接改

| 维度 | 本技能 | 让大模型通读改写 |
|---|---|---|
| 同一实体编号 | 全文统一：`张三` 永远是 `[姓名#1]`，简称「星海智能」与全称「星海智能科技有限公司」自动合并为同一编号 | 容易前后编号打架，长合同几乎必错 |
| 可逆 | `mapping.json` 一对一映射，还原后与原文件逐字一致 | 不可逆，原文丢失 |
| 结构 | DOCX脱敏保留样式、字体和表格；批注及受支持修订默认保留并脱敏；未扫描或未能自动改写内容经一次知悉确认后可原样保留并继续导出 | 常被重排版 |
| 合规 | 首次安装依赖需要联网，安装完成后文书处理不联网；不调云端大模型，只监听 `127.0.0.1` | 合同正文要出境到模型服务商 |
| 可审计 | 每次输出审计日志 + 规则命中报告 | 无 |

**红线**：涉及国家秘密、个人敏感信息批量处理时，仍应先走本单位合规流程；本技能只做技术处理，不替代合规判断。

## 标准工作流

### 1. 先识别，出报告（不要直接改）

```bash
.venv/bin/python contract_sensitive_detector.py 合同.docx \
    --out-dir ./reports --format json,csv,txt,html
```

产出：敏感信息清单（json / csv / txt）+ 一个自包含的复查页 html。
先把清单给用户看一眼，确认哪些要脱敏、哪些要保留（比如甲方自己的名称通常要保留）。

常用参数：
- `--only TYPE1,TYPE2` 只启用指定类型
- `--disable TYPE` 停用指定类型
- `--enable TYPE` 强制启用默认关闭的类型（如 `IPV4`、`MAC_ADDRESS`）
- `--allowlist allowlist.txt` 白名单文件，每行一个值，命中即忽略
- `--min-confidence 0.6` / `--min-severity high` 阈值过滤

### 2. 脱敏

命令行（按类型）：

```bash
.venv/bin/python contract_redactor.py 合同.docx \
    --types PERSON_NAME,PHONE_MOBILE,ID_CARD,USCC,BANK_ACCOUNT \
    --restore-mode
```

按复查页导出结果脱敏（尊重用户逐个勾选的位置，推荐）：

```bash
.venv/bin/python contract_redactor.py 合同.docx \
    --selection 合同.selection.json --restore-mode
```

产出：`<原名>_脱敏.docx` + `<原名>.mapping.json`（占位符 ↔ 原文，可还原）。

**务必提醒用户**：JSON格式的映射文件（`*.mapping.json`）含被替换的原文，须按原件同等保护，不能随脱敏件外发。DOCX不内嵌映射文件；仅在脱敏成功后生成。“下载JSON格式的映射文件”默认未勾选；勾选后在脱敏成功时下载，或在成功结果页单独另存；导出失败时没有本次映射文件可供另存。

批注默认保留并脱敏；也可选择“保留但不脱敏批注”或“移除全部批注”。若批注结构无法安全识别，可选择保留但不脱敏；批注及其关联部件原样保留且不进入mapping，导出前必须确认风险，并人工检查批注敏感信息。工具无法判断批注意见本身是否属于内部信息。

DOCX受支持修订默认保留并脱敏。普通文本框（包括VML/DrawingML结构）和简单未绑定纯文本内容控件中的文字可扫描、脱敏和还原；符合简单VML文字路径结构的文字水印也可扫描、脱敏和还原。受支持的隐藏文字会扫描和脱敏并保留隐藏格式。Word兼容分支可能为不同版本保留文本框的备用显示副本，工具无法确认所有副本都已同步脱敏；页面只显示通用风险说明。脚注/尾注正文、字段指令、复杂绘图水印、图片内容及部分未支持修订可能无法自动脱敏；导出前将风险合并为一次知悉提示，最多列出五类。未能自动改写的已选项保留类型、原文和位置，确认后按原文导出并可在Word中手动处理。低置信候选与按选择保留的信息仅在导出后汇总。普通字段只扫描可见结果，不扫描指令。包损坏、XML无效、写入错位或完整性校验失败仍会拦截。按标准`w:del`/`w:ins`保存的拖动移动文字可按受支持修订处理。完全重合的多类型文字候选合并为一次写回并在mapping记录各类型，部分重叠的连续文字范围合并；mapping还原一次原文。跨制表符、换行等控制符而无法安全定位的已选候选会列入导出前提示。修订目标被接受/拒绝、结构变化、占位符被改写或目标不唯一时，JSON格式的映射文件还原会停止。未发现修订内容、但仅开启修订记录设置的DOCX仍可按原流程处理。

检测到外部关系时，左右对照内容仍会正常显示。DOCX默认移除全部外部关系并保留超链接显示文字；外链图片或对象可能不再显示。选择保留外部关系时，显示文字按可见文字规则扫描，超链接目标中符合规则的敏感信息也会进入候选；目标打开后的远端网页内容、其他类型外部关系目标和字段指令中的网址不扫描。保留关系的风险并入一次导出前知悉提示。移除关系不会删除显示文字，也不会删除字段指令中的网址。

可见网址规则覆盖`http://`、`https://`、`www.`及`.com`、`.cn`裸域名；裸域名默认作为低置信、未勾选候选。PDF链接目标不作为候选；导出前显示可点击链接数量并要求确认移除。页面上印出的网址仍须单独脱敏或遮盖。PDF导出为图片，不保留文本层，不能用JSON格式的映射文件还原。

### 3. 还原

```bash
.venv/bin/python contract_redactor.py 合同_脱敏.docx --restore
```

DOCX还原会按mapping v2定位恢复已脱敏的正文、批注文字和批注插入人字段；修订、样式、字体等结构保持原状。选择“移除全部批注”时，批注结构不会通过mapping恢复，须保留原始DOCX。“保留批注但不脱敏”模式下批注原文不进入mapping，不会随还原流程改变。

### 4. 收尾自查

- 打开脱敏件搜索残留的公司名、人名、电话、账号
- 核对最终导出件及提示列出的未能处理位置；可使用清单中的类型、原文和位置在Word中搜索并手动修改。页眉页脚、备用文本框、脚注/尾注、字段代码、复杂图形水印、图片和未支持修订可能仍含敏感信息
- 确认 `mapping.json` 已归档到受控位置
- **交付 / 共享 / 换机前清理会话明文**：本机会话目录（Windows 默认 `%LOCALAPPDATA%\ContractDesensitizer\sessions`）保存上传原件与PDF页面/文本缓存。打开「历史记录」点「**清理全部明文**」会按当前规则尝试清理工具数据目录内各会话的上传文书副本、PDF私有缓存、项目状态及符合命名规则的映射、日志和临时文件，已完成的脱敏稿保留。电脑原位置上的源文件、浏览器下载或用户另存文件、案件/项目自选规则及会话目录外的文件不在本次范围；不符合命名规则的映射也可能保留。可选设置环境变量`CONTRACT_DESENSITIZER_RETENTION_DAYS=<天数>`启用启动时自动清理（**默认关闭**）。

## 能识别什么

完整规则表见 `references/脱敏规则清单.md`，核心类型：

本地 WorkBuddy 包额外覆盖常见英文公司法定后缀（如 `Limited`、`Inc.`、`LLC`、`GmbH`、`B.V.`、`S.A.`）及紧邻全称的引号简称，二者使用同一主体编号；标题式公司名称中的一个5字符以上小写品牌词仅在前后标题式名称结构完整时识别。英语为主的文书在复核页会显示范围提示；英文识别依赖字段标签、常见格式和法定后缀，不是通用英文实体识别，不能据此确认全文无漏项。

| 类别 | 类型 |
|---|---|
| 主体 | 中英文姓名、企业名称（含简称合并）、统一社会信用代码、身份证、护照、美国SSN/EIN、部分境外VAT及主体登记号 |
| 联系 | 国内手机号、座机、含国家码的国际电话、邮箱、中英文通信地址 |
| 资金 | 银行账号、银行卡号、IBAN、SWIFT/BIC、美国ABA路由号、人民币及常见外币金额 |
| 其他 | 日期、IP / MAC、车牌、URL、统一社会信用代码、组织机构代码 |
| 关闭项 | IPV4、MAC_ADDRESS 等默认关闭，用 `--enable` 打开 |

两个不能踩的已知边界：

1. **扫描件 OCR 会漏识别** —— 建议逐页抽查，重点关注有机器提示的页面；低置信OCR候选由机器按框处理，印章、签名和漏项由用户手工框选。未处理项按原文保留，用户可在一次通用知悉提示后继续导出；导出提示不显示坐标或几何诊断。
2. **占位符本身不会被二次脱敏** —— 工具会跳过 `[姓名#1]` 这类已有占位符，避免重复替换。

### 英语为主的合同

中文姓名重复匹配不扫描更长汉字词内部；若命中两侧均为汉字，仅在紧邻明确主体/姓名角色、称谓或“介词+动作”结构时传播。

英文姓名从明确标签分隔或签署结构提取，支持`attn.`、受控联系人复合标签、标签后的中文斜线/括号说明、成对引号昵称、`By: /s/`等版式；姓名词之间只允许空白或成对昵称引号，避免跨普通词、标点拼接。支持点缩写。拼音姓名仅在`Pinyin Name`、`Name (Pinyin)`、`Chinese Name (Pinyin)`、`English Name (Pinyin)`或`Romanized Name`等明确标签下识别；明确标注的`English Name`、`Chinese Name`和`Pinyin Name`可在同一联系人字段内共用一个编号。中英文公司名仅在同一字段的括号结构或明确的中英名称标签中建立跨语言别名关系；原有同语言公司全称/简称归并规则不变，不按拼写相似度推断跨语言关系。无标签的普通英文词组不会仅因看似拼音而判为人名。高置信确认的拉丁全名按完整词边界查找重复出现处，明确前置尊称与同一完整姓名共用编号；不按同姓或相似缩写归并。英文地址依赖地址标签及街道、门牌、套间或邮编等结构证据；公司名称覆盖一组常见法定后缀和紧邻全称的引号简称。电话、IBAN、SWIFT/BIC、ABA、SSN、EIN、VAT和登记号按格式及上下文触发。英文合同编号会排除单独标签词。以上不是通用英文实体识别，仍须逐项核对，并可用“添加漏识别的字段”补录。

英语诉讼与仲裁文书另覆盖以下受控字段，仍非通用英文实体识别：案号（美国联邦 `1:24-cv-01234`、英国 Claim No.、中性引用 `[2024] EWHC 123 (Comm)`、香港 `HCA 1234/2024`、有仲裁机构词锚定的中文仲裁案号）；法院专名、`IN THE ... COURT` 标题与 `Court:` 标签走法院名称，仲裁机构（HKIAC/SIAC/LCIA/ICSID/CIETAC/SCC等缩写需有仲裁语境，已支持全称归组织机构）；角色标签（Plaintiff/Claimant/Respondent/Counsel for 等）与 caption/`v.`/BETWEEN 限标题区识别姓名；Address for Service 等送达地址；Attorney ID/SRA/Bar 执业号；DOB 数字日期。仲裁员组成行不作为法院名称，仲裁当事人公司名不作为姓名；`the High Court held`、`Court Road`、`the Claimant submitted` 为负例。短 Award No. 与 Our Ref/Matter No. 默认不勾。

凭据信息只按已知令牌格式、私钥/JWT结构，或明确的密码、密钥、会话字段键值结构识别；候选仅覆盖凭据值。`Authorization`需为明确的Bearer/Basic头，`Cookie`需含会话或认证键值。正文中单独出现`authorization`、`session`、`cookie`等普通词不会触发密钥候选。

PDF扫描文字、英文实体识别、坐标遮盖须分别核对。RapidOCR对低于0.70的行最多进行6次局部放大重识别，只采用字符坐标可靠且分数明显改善的结果。实体分表示字段类型判断，OCR分表示文字识别，定位几何独立决定处理模式。定位按逐字符标签局部判断：空格无字形框不计为坐标不完整，一处粗定位不拖累同页精确候选；候选范围优先采用真实字符/词框按行去重保留。实体分低于0.50的候选默认未勾选，仅在侧栏提示，不阻断导出；OCR分低于0.70的候选由机器自动按框处理（代号放不下则遮盖）。OCR分未提供时会明确标示，不按低分处理。没有可靠几何的候选进入“需你确认”红色分组，未处理时按原文导出并在导出前提示。实体分低于0.50但不低于0.30的候选保留显示；低于0.30的规则命中按页计数、在页面和导出提醒提示，计数是未去重的规则命中数。OCR行低于0.35的接收线、文字为空、字符框数量不符、分数无效及分数未提供分别计数，不能据此认为没有敏感信息。策略默认保留的金额、日期会在复核页和导出提醒中列出。上传时须明确选择“脱敏交易要素”或“保留交易要素”；所选策略在PDF、DOCX、TXT和Markdown中使用相同默认选择，不按文件格式自动决定。PDF像素导出不可映射还原。短框优先使用缩短代号，常用类型可显示字母加编号（如机构O1、姓名P1）；不足以容纳至少八点文字时只遮盖，不扩大原框。

### PDF人工复核状态

每个候选提供“自动/遮盖/保留”三态切换，默认处置由扫描完成时的机器自动处置填好（可整体撤销）。“需你确认”分组集中缺少可靠坐标的命中，可到所在页拖框遮盖或明确保留。未知页码单独标示；多个遮盖框可分别完整覆盖跨行候选。补录、同案同步和重试单页保留其他未变位置的人工决定；重试会清空旧撤销记录。“撤销最近更改”可能撤销其他页最近一次候选或遮盖操作。矩形框内的普通正文也会被遮盖，图像旋转后必须对照当前页面重新框选。导出直出：仅扫描进行中不允许导出；识别失败、尚未处理内容、扫描停止或零处置时须一次通用知悉确认；导出提示不显示坐标或几何诊断。机器按框遮盖不构成字形全覆盖证明，以导出预览为准。

## 常见问题

**Q：能不能做成双击图标？**
随包安装器会在macOS桌面生成启动和停止两个`.app`，Windows生成`.bat`入口。技能平台不接受这些安装文件时，只安装技能目录的用户仍可按平台说明从本机脚本启动；自建macOS快捷方式可把`python <绝对路径>/start.py`存成`.command`。

**Q：端口 18800 被占用？**
启动器会自动结束旧服务；也可以手动 `lsof -nP -tiTCP:18800 | xargs kill`。

**Q：JSON格式的映射文件何时保存？**
脱敏成功后生成，默认未勾选下载。您可勾选“下载JSON格式的映射文件”，在脱敏成功后下载；也可在成功结果区单独另存。已授权保存文件夹时，勾选下载后文件写入该文件夹；未授权文件夹时按浏览器下载设置保存。手动另存也按浏览器下载设置处理。导出失败时不会显示本次文件的另存入口。映射文件含被替换的原文，请单独保管，不要随脱敏文书外发。

**Q：浏览器不能自动把文件存回原文件夹？**
浏览器安全限制所致。也可点“选择文件夹”授权后直写到该目录（Chrome / Edge 支持）。未选文件夹时，浏览器可能询问保存位置，也可能按浏览器设置保存；请检查输出文件名，如含敏感信息请自行重命名。

**Q：脱敏后能否再编辑正文结构（删段落、改表格）？**
可以，但还原依赖占位符与原文一一对应；删掉含占位符的段落会让该处无法还原，其余不受影响。

**Q：会联网吗？**
首次安装依赖需要联网，安装完成后文书处理不联网。默认`enforce_offline()`阻断外联；服务只绑定`127.0.0.1`供本机浏览器访问。确有需要时才用`--allow-network`显式放开。

**Q：印章、签名、图片能自动脱敏吗？**
不能自动识别——检测全部基于文字。DOCX / TXT / Markdown **不扫描内嵌图片**，DOCX图片会随文保留并在复核页提示人工核对；PDF可对印章 / 签名**手动拖动框选**遮盖，但**像素填黑、不可还原**。PDF批注及批注人名称可能作为页面内容保留，工具不能单独识别并替换作者信息，必须人工核对。

**Q：低置信内容会不会被直接丢掉？**

DOCX、TXT和Markdown复核页使用低置信提示，导出前提醒人工复核，不展示分数。PDF页分别展示实体识别分数和OCR文字识别分数：实体分低于0.50、OCR分低于0.70的候选默认未选，须明确处置；字符级坐标可靠时可直接勾选，不因分数低而要求重画。只有定位几何不可靠时才需要框选或明确保留。实体分低于0.30的规则命中不列在候选清单中，按页提示并进入导出提醒；计数是未去重命中数。低于0.35 OCR行接收线、文字为空、字符框数量不符和分数无效分别计数并提示人工检查，不能据此认为没有敏感信息。

**Q：会话目录安全吗？**
首次安装依赖需要联网，安装完成后文书处理不联网。服务只绑`127.0.0.1`，但**本机任何进程**都能访问该端口与会话目录（含明文原件）——**本机即信任边界**。不要把端口暴露到本机之外；交付 / 共享 / 换机前请先「清理全部明文」。

## 英文姓名、公司与DOCX检查补充

英文姓名仍须依赖受控字段标签；表格中的`BUSINESS OWNER DETAILS`、`COMPLETED BY`和`SIGNATURE`可引导姓名扫描，`DATE COMPLETED`作为非姓名字段边界。不会因普通大写词组或标题式单词自动判定为姓名。英文机构须符合公司名称结构；`AS`和`A/S`仅按大写法定后缀处理，不把句中的`Company as`或`We,`并入机构名称。

自动识别无法穷尽DOCX中的全部敏感信息，识别结果也可能有偏差；外发前请人工核对导出的文件。页眉页脚中的可提取文字参加扫描，图片、文本框、字段及其他结构仍可能有漏项。脚注/尾注正文、字段指令、备用文本框和未支持修订等风险合并显示为一次导出前知悉提示，不再渲染逐项检查表；未能自动改写的已选项会列明类型、原文和位置。确认后可继续导出，未处理内容按原文保留。DOCX包损坏、写入错位或完整性校验失败仍会阻止导出。符合严格结构条件的VML文字水印可带一个被形状引用、无可见文字的静态形状模板。

### Word页眉页脚与PDF可见画布

Word普通、首页和偶数页的页眉页脚均纳入文字扫描、位置复核、脱敏及映射还原；多个节共用的部件只处理一次。检测到页眉页脚仍会提示人工核对图片、字段及复杂结构，不能据此推定已全部处理。

PDF预览、OCR和导出均初始化交互表单外观，表单中可见文字按本机OCR结果复核；导出仍为静态像素稿，不保留可填写表单或原始字段树。若表单值与外观不一致，须先用原PDF软件另存核对后的副本。裁切页面的候选坐标以裁切后的可见画布为准。明确中文电话、邮箱、银行账号、金额或日期标签内，满足完整格式校验的分字间隔会合并并保留原字形坐标；不合并普通英文正文或跨栏内容。旋转或倒置页面若缺少可靠字符坐标，继续手工框选，可适当覆盖字段标签，以同时覆盖实际文字和候选范围；不得只凭候选文字正确就认为遮盖位置正确。

PDF导出清单按实际处置状态分别显示低分未勾选OCR候选的已处置数和待处置数；完整框选或明确保留后不再笼统提示为未处理，仍须核对最终预览。

### 减少导出误拦与导出确认（DOCX相关）

（1）PDF复核候选提供“自动/遮盖/保留”三态切换，一键遮盖即完成绑定，无需二次确认；早期版本的批量选框与逐页确认流程已移除。

（2）多个框联合完整覆盖同一处文字时可计为已遮盖；有实际缝隙仍须补框。修改、删除关联框会使相关确认失效，须重新检查；只需重新核对受影响页。绿色表示已替换或已遮盖，灰色表示明确保留或按策略保留，橙色表示尚待处置。颜色不能替代导出清单。支持明确多选后批量保留原文，该操作与遮盖分开。

（3）普通文字控件的字体、段落及定位格式，以及完整的PAGE、NUMPAGES、SECTIONPAGES页码域（含安全格式开关、拆分指令、无缓存结果）不再因这些格式误拦。数据绑定、未知结构、未闭合域和外部指令仍按实际风险检查，不因控件名像页码就放行。上传复核页显示已分类的控件预检；不能据此保证所有复杂对象可导出。

（4）已选修订人属性按物理位置、旧值构造预期变化，各阶段校验同一预期；未选文字和结构仍受保护，不自动接受或拒绝修订。普通无修订DOCX预先计算正文及页眉页脚的逐段预期文字，明确未勾选的同值位置不会被当成页码控件残留。其他属性和复杂结构的全局同值误拦仍有兼容边界。

（5）可以明确确认“无替换导出”：替换0处，保留未选原文，仍执行结构检查和所选清理。没有可还原替换记录时不提供映射文件；不会改用旧映射，也不会因类型全未选而自动启用全部。浏览器导出清单绑定当前原件、选择、模式及规则快照，选择变化后须重新确认。旧客户端沿用既有确认检查；此快照不是用户认证机制。

（6）识别增加户籍地等地址标签及受控行政层级续行，修正机构名称内部连词造成的前缀截断；支持受控的“姓名律师”“律师姓名”及已确认姓名的律师语境传播。姓名替换保留“律师”称谓。识别仍可能漏项，地址换行不按任意正文无限续接。
