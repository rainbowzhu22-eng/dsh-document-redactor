# 合同脱敏规则清单

> 本文件是脱敏规则的**唯一配置源**，供 `contract_sensitive_detector.py`（识别）与
> `contract_redactor.py`（改写）共同读取。**直接编辑本文件即可增删改规则，无需改代码。**
>
> 运行方式（二选一）：
> 1. 把本文件与脚本放在同一目录，工具自动加载；
> 2. 显式指定：`python contract_sensitive_detector.py 合同.docx --rules 脱敏规则清单.md`
>
> 想跳过本文件用内置默认：`--rules /dev/null`（macOS/Linux）。

## 修改规则：交给 AI Agent 帮你改

1. 软件会自动保留最近一次通过校验的规则版本（规则目录 `Rules/Backups/last_valid.md`）；重要修改前也可手动另存副本。规则内容变化时才生成新快照，同一内容不会重复备份。
2. 把本文件全部内容和你想修改的要求粘贴给你自己选择的 AI Agent。只发送规则和虚构示例，不要发送真实合同、客户信息或原文映射；完整规则文件会离开本机，是否到达云端取决于你选择的 AI 服务。
3. 保存 AI 返回的完整内容时使用 UTF-8 编码，不要混入解释文字；只有 `## 规则表` 标题下的连续表格行会被解析为规则，整份内容不要用代码围栏（三个反引号）包裹。
4. 回到工具重新上传虚构测试文件核对识别与导出；出错时可在页面恢复上一份有效版本。AI Agent 只在修改规则时使用；安装和日常脱敏不需要 AI Agent。

可复制的提示词：

> 我想修改合同脱敏规则。请只按我的修改要求调整下面的规则清单，保留其他规则、表格结构和程序需要的字段，不修改程序代码。除非我明确要求删除某条自定义规则，否则请保留全部现有规则行和正则表达式；如果有内容无法保留，请先指出，不要自行删行。请返回可以直接复制回原文件的完整Markdown内容，不要省略未修改的部分，也不要用代码围栏包裹全文；最后另行说明改动和仅使用虚构信息的测试方法。我的修改要求是：【在这里填写】。以下是当前规则文件的全部内容：【在这里粘贴】。

## 列说明

| 列 | 含义 |
|----|------|
| 规则名 | 类型 ID（已有 ID 修改属性；新 ID 必须在最后一列填正则） |
| 严重度 | 高 / 中 / 低（用于复核页按高中低分类筛选） |
| 掩码方式 |给人看的说明，程序不解析 |
| 掩码参数 | 分号分隔的 `key=value`。可用 key：`keep_head`（保留前 n 位）、`keep_tail`（保留后 n 位）、`replacement`（整串替换，如 `[已脱敏]`）、`mask`（命名策略，见下表）。`replacement` 与 `mask` 互斥，后写的生效 |
| 默认启用 | 是 / 否 |
| 正则 | 仅**新增**规则时必填。正则里的竖线请写成 `\|` |

命名策略（`mask=`）：`person` 姓氏+`**`、`passport` 留首字母、`hk_id` 香港身份证、
`landline` 留区号后 4 位、`address` 留省市区县、`ipv4` 留第一段、`mac` 留前 2 位、
`secret` 全遮 `[已脱敏]`、`amount` → `¥******.**元`、`email` 留首字母与域名。

网址候选覆盖`http://`、`https://`、`www.`及以`.com`或`.cn`结尾的裸域名，支持常见路径、端口、查询参数和片段；网址语法由URL解析器校验。有效显式网址启发式分为0.62，格式可疑时为0.42；有效裸域名启发式分为0.42，格式可疑时为0.32。实体复核线为0.50，候选展示下限为0.30，所以裸域名仍可见但默认不勾选，核实后可勾选替换。上述分数是规则启发式值，未使用有标注样本统计校准。邮箱地址继续按`EMAIL`识别，不重复作为网址候选。DOCX选择保留外部关系时，显示文字按正文规则扫描，外部超链接目标中的可识别敏感内容也作为候选；目标打开后的远端网页内容、其他类型关系目标及字段指令中的网址不扫描。PDF链接目标不作为候选。

姓名上下文补充：无冒号姓名标签使用明确字段词清单；“员工”“法人”等普通行文词不单独作为强姓名标签，因此“法人和非法人组织”等表述不会仅因紧跟两字短语就默认勾选姓名。“员工：覃敏”等明确冒号字段仍按原规则识别。英文姓名仅在`Contact Person`、`Name`、`By`、`Director`、`Signed by`等受控标签附近提取，不做通用英文人名识别。修订DOCX分别组装接受/拒绝修订视图后扫描，拆在多个底层文字片段中的候选按组合文本识别，并按实际XML片段定点脱敏和mapping还原。完全重合的多类型目标合并为一次写入，并列各类型占位符；连续部分重叠范围按并集写入，mapping记录所有类型和原文、还原时恢复一次。无法安全组成连续文字、物理结构不一致或写入位置校验失败时仍停止写回。

英文规则补充：英文地址只在`Address`、`Registered Office`、`Notice Address`等标签附近匹配，并要求门牌/街道/套间/邮编等结构证据；公司名识别覆盖代码内列明的一组常见法定后缀，及与全称紧邻的引号简称。国际电话依赖国家码与号码结构；IBAN执行国家长度及MOD-97校验，ABA路由号执行校验位检查；SWIFT/BIC、EIN、VAT和公司登记号依赖明确字段标签。英文姓名在受控标签后可附带中文斜线/括号说明；同一联系人字段内明确标注的`English Name`、`Chinese Name`和`Pinyin Name`可建立同一自然人的别名编号。中英文公司名只在同一字段的括号结构或明确中英名称标签中建立跨语言别名关系；原有同语言全称/简称归并规则不变，不按字符串相似度推断跨语言关系。拼音姓名仅在`Pinyin Name`、`Name (Pinyin)`、`Chinese Name (Pinyin)`、`English Name (Pinyin)`或`Romanized Name`等显式标签下识别；无标签的普通英文词组不会因词形而自动作为姓名。以上规则不是通用英文实体识别。英文为主的文书会显示范围提示，扫描PDF的文字读取和实体识别须分别核对。

英文姓名与编号边界：普通英文姓名标签要求冒号、竖线或is等明确分隔，行首By签署与Signed by结构单独识别。连续英文姓名词之间仅允许空白，支持首字母点缩写；高置信拉丁全名按包含变音字母、数字、撇号、连字符的边界传播。明确前置尊称只用于同类型编号归并，映射保留各处原文；不按姓氏或相似缩写归并。CONTRACT_NO精确排除单独的agreement、contract、reference、invoice、purchase、number、order、ref、no标签词，保留其他纯字母编号。

英语姓名边界补充：在受控边界内支持`attn.`、列明的联系人复合标签、成对引号昵称，以及“contact for ... is”最多三个中间词的叙述标签；签署姓名可处理`By: /s/`、`By /s/`和`By:`。不把任意句点、任意未配对引号或普通三词短语当作姓名边界；姓名词间昵称引号只在成对结构中允许。

英语姓名/机构及DOCX结构补充：表格姓名支持`BUSINESS OWNER DETAILS`、`COMPLETED BY`和`SIGNATURE`等明确标签，并以`DATE COMPLETED`等非姓名字段作为探测边界。普通语句中的`Company as`及`We,`不作为机构名称的一部分；`AS`和`A/S`作为大写法定后缀匹配，仍须满足机构名称结构。页眉或页脚含内容时，复核页提示在Word中人工检查；可提取文字会扫描，但图片、文本框、字段等结构仍需检查。未扫描的脚注/尾注、图片文字、字段指令、兼容文本框、未支持修订按可盘点范围以表格提示检查对象和处理要求，并要求导出确认；无法安全定位的复杂结构阻止导出。支持仅含一个非空VML文字路径及一个被形状引用的静态空文字模板；复杂或带额外文字对象的VML结构仍不自动处理。

PDF OCR复核与处置：RapidOCR对低于0.70的行最多重试6行局部放大识别；只有字符级几何、分数达到0.70且改善超过0.05时采用，失败保留原结果。候选分别保存实体分、OCR分和定位几何；实体自动勾选/复核阈值为0.50，OCR自动勾选/核字阈值为0.70，两类分数分别判断，不合成为最低分。实体分0.50至0.70的候选不因低于0.70而自动转人工复核。OCR分低于0.70的候选由机器自动按框处理（代号放不下则遮盖）；实体分低于0.50时默认未勾选，仅在侧栏提示，不阻断导出；缺少可靠坐标的命中进入侧栏“需你确认”分组，未处理时按原文保留并可在通用知悉提示后继续导出，提示不展示坐标或几何诊断。短框缩为简短代号或常用类型字母加编号，至少八点字号仍不适配时仅黑色遮盖。局部OCR重试不保证读字完整。

旧版PDF项目若只保存实体分和OCR分取低值后的综合分，迁移时保留该值并标记旧分数语义，不将综合分推算为实体分或OCR分；旧项目不重新OCR，已有勾选、明确保留和手工遮盖全部保留，可直接导出。新项目的规则分是启发式值，未经过有标注样本的概率校准。

PDF定位与导出策略：检测到但缺少可靠坐标的命中进入“需你确认”清单，保存失败原因、可用页码/文本范围及OCR分数；相同类型、页码、文本块及字符范围的重复记录合并。未处置项不再硬拦导出，改为对尚未处理内容显示一次通用知悉确认，确认后可继续导出，未处理内容按原文保留；导出提示不展示坐标或几何诊断。手工框选自动绑定单项，无需确认弹窗；操作者仍须核对实际遮盖范围。服务端校验框选有效且在页内。策略默认保留的金额、日期不进入缺陷门禁，但复核页和导出摘要显示数量。不提供格式推荐模式，须用户显式选择。PDF输出仍为不可映射还原的像素稿。

机构名称复核说明：分公司/子公司名称前若有具体行政区划、合同主体/独立字段标签或嵌套法定机构名称，可按机构候选识别；缺少这些名称证据的宽跨度候选会降为低置信人工复核，默认不替换。“通知分公司”“包含分公司”“不含分公司”“包括各分公司”等泛指引用结构不作为机构名称候选。序号后接“协会”等通用类别但没有具体名称的表达也不作为机构名称候选，例如“(iii)协会”“（三）协会”；具名协会仍按规则识别。

统一文书流程会将`CASE_NO`格式命中进一步分类为“诉讼案号候选”“公文/机构编号候选”或“编号候选，类别待核对”。类别待核对项默认不勾选；分类只依据编号的格式，不推断其实际来源。法院名称由独立规则识别并单独选择。PDF、DOCX、TXT、MD均按同一识别配置展示这些候选。

英语诉讼/仲裁受控规则：英文法院名称走`COURT_NAME`，仲裁机构全称和仲裁语境中的`HKIAC`、`SIAC`、`LCIA`、`ICSID`、`CIETAC`、`SCC`缩写走`ORG_NAME`；孤立或缺少仲裁语境的缩写不触发该缩写规则。`Tribunal:`后的仲裁员角色行、仲裁机构名称不归入法院候选。中文仲裁案号只按包含可核实仲裁机构名称/简称并符合案号结构的格式进入诉讼案号候选；一般公文号、公司编号、会议编号和期次通知不因带年份与“第…号”而误作仲裁案号。英文当事人角色标签后的完整公司候选保留为`ORG_NAME`，不再被优先级较高的姓名候选覆盖。选择“保留交易要素”时，金额和日期按既有策略默认保留，包括仲裁裁决金额、仲裁费和裁决日期；需对外隐藏时逐项选择脱敏。

PDF各页均尝试本机OCR补充识别；有文字层页面保留文字层并按位置合并OCR重复候选。表格单元格和独立栏位分开匹配，单元格内换行按同一字段处理。跨行候选按字符行分别显示和遮盖；空间不足以放置代号时清除命中原字，不扩大遮盖范围。补充OCR失败或无结果时进入人工检查提示，仍须逐页核对候选和导出预览。

## 如何新增规则

在表格末尾追加一行，`规则名` 用新的英文 ID（不得与现有规则名重复，序号也请使用未占用的新编号），最后一列填正则即可。以新增“员工工号”为例：规则名写 `EMPLOYEE_NO`，类别写 `商业信息`，严重度写 `中`，掩码方式写一句给人看的说明，掩码参数写 `keep_head=2; keep_tail=3`，默认启用写 `是`，正则列写 `工号\s*[A-Z]\d{8}`（正则里的竖线请写成 `\|`）。此处刻意不列出完整的竖线分隔示例行，避免示例被当作规则。

只有 `## 规则表` 标题下的连续表格行会被解析为规则；说明区、示例与检查清单中的表格和代码围栏不参与解析。保存后重新上传文书即生效；复核页面会自动出现新类型供勾选。

## 与复核页/改写工具的关系

- `contract_sensitive_detector.py`：按本表识别候选，生成复核页（脱敏前后对比）；
- 复核页勾选（按高中低分类筛选）→ 确认后生成 `*.selection.json`；
- `contract_redactor.py`：读取选择文件，对 docx/pdf 执行真正的脱敏改写。

DOCX复杂格式按结构安全范围处理：正文、表格、页眉和页脚中的普通VML/DrawingML文本框、符合严格结构条件的VML文字路径水印、简单未绑定纯文本内容控件及受支持隐藏文字纳入扫描、替换和映射还原；外发清理校验其结构并保留隐藏格式。Choice/Fallback兼容分支可能保存同一文本框的不同版本备用显示内容，例如VML与DrawingML文本框副本，工具无法确认所有副本都已同步脱敏，会并入简短知悉项。脚注/尾注正文、字段指令、复杂水印、图片文字和部分未支持修订可能无法自动脱敏；未能自动改写的已选内容会按原文保留，并提供类型、原文和位置供用户导出后手动处理。未处理内容不会写入mapping，也无法由mapping还原。导出前对实质风险只要求一次知悉确认，最多展示五类；确认后可继续导出。低置信候选和按选择保留的信息仅在导出后摘要提示。DOCX包损坏、XML无效、写入错位或完整性校验失败时仍阻止导出。

DOCX写回会在物理目标层合并重叠候选。同一文本范围同时命中`BANK_ACCOUNT`与`BANK_CARD`等多个类型时，导出执行一次写入，结果并列显示各类型占位符；连续的部分重叠范围按其并集写回。mapping保存全部类型与原文，恢复时只恢复一次。结构位置不一致、范围无法组成连续文本或写入校验失败时仍按技术完整性错误处理。

## 占位符编号规则（重要）

脱敏产物统一使用 `[类型标签#N]` 形式的**占位符**（例如 `[自然人姓名#1]`、
`[组织机构名称#2]`），并同时产出 `mapping.json` 用于一键还原。

编号遵循两条铁律：

1. **同一个实体，整篇共用一个编号。**
   张三在第 1 段和第 30 段出现，都写成 `[自然人姓名#1]`；
   不会出现「人1 / 人7 / 人23」这种一个人占多个号的情况。
   —— 否则一份合同会冒出几十个人名编号，审核时无法判断「人7 是不是刚才的人1」。

2. **不同实体，各自占号，编号按文档中首次出现的先后顺序分配。**
   文中第一个出现的人是 `#1`，第二个是 `#2`；机构名、信用代码等各自独立编号。

### 简称（同一主体的另一种写法）

企业名称常写成「北京星海智能科技有限公司（以下简称"星海智能"）」，正文则用简称。
**全称与简称共用同一个编号**，写法包括：

- 显式定义：紧跟全称之后的 `（以下简称"X"）` / `（下称 X）` / `（简称 X）`；
- 自动推算的字号：由全称去掉行政区划前缀与机构类型后缀得到，例如
  `北京星海智能科技有限公司` → `星海智能科技`；
- 分支机构：`XX 有限公司上海分公司` 与 `XX 有限公司` 视为同一主体。

文件、期限、合同角色和业务通称不作为机构简称传播。例如“平台”、“合作商户”、“披露方”、
“接收方”、“授权方”、“运营方”、“关联方”、“个人信息处理者”等，即使出现在简称定义语法中，
也保留原文，不替换为机构占位符。该排除按完整词条判断，不按“平台”“商户”等子串扩大匹配。

不同主体不会被误并（例如 `中国工商银行` 与 `中国银行`、`招商银行` 与 `中信银行`
各自独立；`上海分公司` 与 `北京分公司` 各自独立）。

### 还原

- 新生成的 DOCX 不内嵌原文映射；`mapping.json` 单独生成并按原件保管，不能与外发稿一起发送；
- 还原时同一个占位符会**按出现位置**还原成各自的写法
  （全称还原成全称、简称还原成简称），因此还原稿与原文逐字一致；
- 可直接把脱敏稿拖回复核页选「还原」，或命令行加 `--restore`。

### 输出与保存（复核页底部）

点「确认并执行脱敏」后，脱敏稿始终生成；JSON格式的映射文件仅在脱敏成功后生成，“下载JSON格式的映射文件”默认未勾选。用户可主动勾选，在脱敏成功后下载映射文件，也可在成功结果页单独另存：

| 文件 | 是否默认 | 用途 |
|---|---|---|
| `xxx_脱敏.docx` | 是（必选） | 交付给对方的脱敏稿 |
| `xxx_脱敏.docx.mapping.json` | 默认不自动下载，文件仍会生成 | 还原用的对照表，单独保管，不得外发 |

保存位置有两种：

1. 点「选择保存文件夹…」并授权后，脱敏稿及主动勾选的mapping写入所选文件夹。
2. 未选择文件夹时，浏览器可能询问保存位置，也可能按浏览器设置的位置自动保存。

输出名沿用源文件名。请检查文件名，如包含敏感信息，请自行重命名。

> 如需日后还原，必须保存与脱敏稿对应的JSON格式映射文件。仅有脱敏DOCX不能还原；外发时不要附带映射文件。导出失败时不会显示本次文件的另存入口。

复核页里逐个点掉的高亮位置会**真的不替换**（服务端按绝对偏移精确匹配，
所以预览看到什么，产物就是什么）。若白名单因文档被改动而完全对不上，
程序会退化为「按类型全量脱敏」而不是静默输出一份没脱敏的文件。

合同编号补充：支持`Contract Reference`标签；单独的agreement、contract、reference等标签词不作为合同编号，纯字母自定义编号仍可识别。

姓名传播与公司名称补充：英文公司后缀候选允许一个5字符以上的小写品牌词，但要求其前后仍符合标题式名称结构；未满足此格式的英文公司名称仍可能漏识别。已确认中文姓名的重复传播不匹配更长汉字词内部；命中两侧均为汉字时，须有明确主体/姓名角色、称谓，或“介词+动作”结构。

PDF复核一致性：同页、同类型、位置重叠的金额候选在去重时统一半角/全角逗号和小数点，避免文字层与OCR重复覆盖同一金额；不将该标点归一化用于姓名等其他类型。跨行候选可由多个手工框分别完整覆盖各行。PDF展示实体识别与OCR分数、待办数量及逐项处置要求；文字格式的低置信提示口径不套用于PDF。人工框选覆盖框内全部像素，包含与水印或签名重叠的普通正文，必须核对预览。

页眉页脚与PDF读取范围补充：普通、首页及偶数页页眉页脚均按实际定义部件扫描，共享部件去重。PDF裁切坐标跟随可见画布；交互表单外观加入预览与OCR，导出仍为静态像素稿。明确中文电话、邮箱、银行账号、金额、日期标签内的分字间隔仅在完整值格式校验后合并，不改变字段类型、默认选择或普通英文正文。

### 规则及处置边界补充

地址识别补充户籍地、户籍地址、户口所在地、现住址、现居住地等标签；无冒号形式须有地址结构证据，行政层级断行最多受控续接两次，保留原始偏移。门牌、楼栋、楼层内部空格在标签路径中保留，不吞入下一姓名、主体或地址标签。

机构名称内部的“和”“与”“及”不单独构成左边界；当左侧已形成完整机构后缀时，仍作为两个并列主体处理，避免截掉机构前缀或把两家机构合并。

“姓名律师”“律师姓名”复用自然人姓名类型，结合姓氏、复姓、长度、停用词、右边界和有限动作尾词识别；律所名称与姓名分别定位，仅替换姓名。示例“覃敏律师”“律师覃敏”中的姓名共用编号；“律师费用”“律师应当履职”“委托律师出庭”不据此产生人名。该规则不是对任意中文自由文本的人名完整性保证。

PDF实体分、OCR分和定位几何分别影响处理；实体分低于0.50或OCR分低于0.70时默认未勾选或由机器按框处理，二者不取最低分合成。定位按逐字符标签局部判断，候选范围优先采用真实字符/词框按行去重保留；有真实框的候选均可按框处理，只有缺少有效坐标才需人工。粗定位候选由机器自动按框处理并在侧栏标注；缺坐标项进入“需你确认”。多个遮盖框按实际绘制像素求并集，有缝隙不得用外接矩形冒充覆盖。PDF导出按钮前持续显示自动识别边界及外发前人工核对提示，该提示不要求确认、不阻断导出。明确保留原文不等同于脱敏；导出按尚未处理风险显示一次通用知悉确认，导出提示不展示坐标或几何诊断，请对照导出预览抽查。

PDF定位、机器自动处置与导出直出：OCR与文字层均引入与文本索引一一对应的逐字符定位标签（缓存版本7），空格无字形框不计入“坐标不完整”，一处词级/行级粗定位不再拖累同块其他精确字符；候选范围优先采用真实字符/词框去重后按行保留，跨行不合并为总外接框；旧缓存缺数组时保留旧精度标签，不推断为精确。扫描完成后机器自动处置：能精确改字的自动替换；有真实框但不能精确改字的（OCR分低于0.70、词/行级定位、跨行分段）自动按框处理，代号放不下则整体遮盖，行级框可能连带同行少量正文并标注，可整体撤销；实体分低于0.50的候选与编号候选不自动处理仅侧栏提示；缺坐标命中入“需你确认”。复核界面为“自动/遮盖/保留”三态，删除批量遮盖四按钮与逐页核对流程，取消全部阻断式确认弹窗。导出直出：仅扫描进行中不允许导出；识别失败、尚未处理内容、扫描停止或零处置时须一次通用知悉确认，提示不展示坐标/几何诊断；链接移除改为软提示；旧复核版本号不再阻断，按最新快照导出并返回实际导出版本。机器按框遮盖不构成字形全覆盖证明，以导出预览为准；未处理内容按原文导出。
