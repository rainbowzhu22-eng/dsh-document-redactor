# 文书脱敏 · DSH 插件 1.3.1（开发预发布）

1.3.1接入Windows OCR/恢复和Word可读属性修复，补回PDF规则快照、规则变更拦截及明确处置门禁，并允许插件内映射下载正常显示确认框。运行时代码沿用已在macOS Apple Silicon、官方DSH 0.2.1-rc.2完成Web和真实桌面定向实装的修正候选；本次发布构建仅同步说明及溯源元信息。Windows实机、合并版全量回归及Word原生版式仍未覆盖，保持开发预发布。原R99来源见core/BASELINE.json，合并来源及摘要见core/RETURN-MERGE.json。macOS优先使用系统Python，避免宿主随包Python的签名限制；不修改DSH应用或其签名。

安装插件后，从侧栏“文书脱敏”进入，DSH侧栏自动收起，点击“打开脱敏工具”。第一次会在独立目录建立Python环境和安装依赖，需要联网；打开后使用原版蓝紫视觉的上传、复核、导出页面；顶部、文书页面与规则助手统一字号及按钮规范。历史记录统一放在插件顶栏。“返回DSH”返回宿主；“更多”提供停止工具。文书处理全流程留在插件内。关闭面板不会删除项目；停止只结束本插件进程。宿主进程退出时，私有管道关闭会通知工具自行关闭本机服务。

首页及右上角“帮助与反馈”均可扫码加入脱敏工作台技术交流群，无需先启动Python环境。沿用开源DPIA工作台的动态群码策略，从`https://xingchendata.com/community/redaction.json`读取配置；对应入口显示、返回前台及可见时每五分钟刷新。过期、满员、暂停或失败不保留旧码，有有效备用群则切换，错误态可重试；个人网站为备用联系入口。离开页面、隐藏或关闭帮助时停止该处自动读取；首页仍可见时其群码继续更新。获取配置和图片不附带文书、规则、映射或对话。维护者通过官网配置换码或标记满员，不需要重装插件；插件不会创建微信群码或自动检测微信群容量。

支持R99的Word、文字/扫描/混合PDF、TXT和Markdown流程。PDF已检出敏感项须处理或明确保留，规则改变后旧项目须重新上传；PDF导出不能用映射恢复，原件从本机项目取回。文字文书及映射还原沿用原工具。自动识别可能漏项，外发前须人工检查。

处理服务仅监听本机127.0.0.1。首页、复核页及右上角“识别规则”均可进入Agent规则助手：描述需求→生成方案→查看差异→应用。使用DSH配置的模型，只提交当前规则与主动填写的需求，不自动提交上传文书、候选原文或映射；助手没有文件、终端或其他工具权限。应用前使用R99解析器校验并检测并发修改，保留原规则备份。当前文书需重新上传识别，现有导出文件不会自动改变。取消或失败不改变生效规则。未应用的有效方案可在重开工具后恢复。

数据默认位于当前DSH主目录下的`document-redactor/`（会话`sessions/`、规则`rules/`、Python环境`environment/`），与插件代码分开。升级插件保留该目录。环境失败可检查本目录的`environment.log`并重试；管理者可用`DSH_REDACTOR_PYTHON`指定Python 3.9以上的可执行文件。规则内容不可放真实客户资料。

R99底层许可及版权行见LICENSE，固定引擎来源摘要见`core/BASELINE.json`。群码控制器改编自Apache-2.0许可的开源DPIA工作台，声明见NOTICE，许可全文见`licenses/Apache-2.0.txt`。Safari、Word原生、Windows新PDF门禁及Intel等原有限制继续存在；当前不是正式版，不代表跨平台或真实文书总体准确率验收通过。

数据说明：文书解析与改写由本机引擎完成；规则助手会提交当前规则全文和主动填写的需求，使用云端模型时需要联网。本机回环监听只说明文书处理服务的绑定地址，不保证整个DSH宿主仅本机可访问。历史项目清理不覆盖原位置源文件、已下载文件、规则与备份、DSH Agent对话或模型服务侧可能保留的记录；处理中可能拒绝相应清理，删除不等于安全擦除。Word特殊对象支持范围未因接入规则助手而扩大，仍须按格式说明人工复核。

1.3.0 发布说明（历史，仅适用于已发布旧包）：按维护者决定统一插件版本号，运行时代码与已验收的0.3.1-dev一致；Windows仍待实机验收，版本号不表示跨平台测试已通过。底层R99的1.3.0-dev来源版本记录保留。
