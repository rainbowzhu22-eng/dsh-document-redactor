## 安装

1. 在DSH侧栏打开“插件 → 添加插件”，填写TGZ文件的**完整路径**。无需解压。
2. macOS：Finder选中文件，按Option＋Command＋C复制路径。例：`/Users/你的用户名/Downloads/dsh-document-redactor-1.4.0.tgz`。
3. Windows：Shift＋右键选择“复制文件地址／复制为路径”。粘贴后**删除最外层双引号，保留路径里的空格**。例：`C:\Users\你的用户名\Downloads\dsh-document-redactor-1.4.0.tgz`。
4. 示例只是路径格式，须使用实际位置。仅填文件名会被当作在线包名查询；切换下载源不能修正这个问题。
5. 按DSH提示启用或重启，再进入“文书脱敏 → 打开脱敏工具”。Windows与macOS使用同一TGZ。

终端安装须先在DSH菜单“管理dsh命令…”注册命令，并从菜单／托盘退出DSH；在TGZ所在目录执行：

```sh
dsh plugin --profile desktop add "./dsh-document-redactor-1.4.0.tgz"
```

终端中的引号用于保护路径；桌面安装输入框删除外层引号。

## 本版新增与使用

- 下载依赖时可选择系统默认、PyPI官方或清华TUNA源；显示准备阶段。失败、取消或超时后可切源重试，保留已安装依赖与缓存；不修改系统pip配置。本机实际验收中TUNA达到20分钟上限，同一环境切官方源后成功；不同网络结果可能不同。
- 依赖清单已声明UTF-8；Windows不应再要求用户手改中文注释。Windows自检包含OCR组件与模型。
- 可正常渲染的结构异常PDF，在原件链接统计失败时提示数量未知并继续复核；导出仍像素重建并检查链接。
- 规则助手支持放弃方案和按应用记录回退。回退先核对差异，恢复到该记录变更前的完整规则，后续修改也会撤销。删除自定义规则仍要确认；重新上传遇到原有删除门禁时，核对后点击“确认删除并继续”。旧项目与既有导出不自动改写。
- PDF原页展开“逐行核对本页OCR文字”，可查看未命中规则、低分或无坐标的行。有坐标时点击定位；人工核对标记单独保存，不解除候选处置门禁，也不要求逐行点击。重新识别后本页标记失效。

## Windows现场核验步骤

只用虚构材料，保留已有项目与规则，不清空日常数据。

1. 记录Windows、Python和插件版本，按完整TGZ路径安装；若现场使用旧pip，确认依赖清单无编码异常，不手改文件。
2. 首次打开，观察准备阶段；完成后上传含虚构手机号的扫描PDF，确认实际OCR可用。
3. 在隔离测试数据中模拟下载失败或取消准备，重开后重试；必要时切换下载源。确认不再反复清空已安装依赖，也不清除文书、映射、规则或备份。请勿为模拟故障破坏日常环境。
4. 重开已准备好的工具，确认复用环境；在测试副本缺OCR组件／模型时，应识别准备不完整，而不是显示可用后才扫描失败。
5. 用两页照片／扫描PDF完成识别、逐行核对、点击定位、补框及导出。核对页数、方向和遮盖位置；真正不可读或未解密文件应明确报错。
6. 用虚构规则验证放弃方案后重开不恢复、应用后重新识别、按记录回退和删除确认；重新上传并检查实际导出。核对旧项目规则变化时仍阻断导出。
7. 升级前后核对原有规则、备份、项目和映射保留。反馈版本、步骤和结果；日志仅取错误附近必要几行，先遮盖账号、用户名、代理等信息，不发送真实文书或映射。
